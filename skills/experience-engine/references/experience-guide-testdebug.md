# 测试脚本调测 — 经验检索配置

本文件配置“测试脚本调测”场景下的经验检索业务规则。
通用调用协议见 experience-engine 的 SKILL.md，本文件配置本场景下要传什么值。

## 一、基本信息

| 配置项 | 内容 |
|--------|------|
| 场景名称 | 测试脚本调测经验 |
| `scene_id` | `421` |

产品名称由脚本从已有调测环境自动获取，无需在本文件配置。识别失败时会明确提示，并继续按场景不限产品检索。

调用人工号由脚本使用 `getpass.getuser()` 自动获取，无需在本文件配置。

## 二、检索经验配置

| 配置项 | 内容 |
|--------|------|
| 什么时候检索 | 1. 进入 Step 2 失败原因分析时，第一个动作必须检索；2. Step 4 修复验证循环中，出现与上一轮不同的新报错时，必须重新检索 |
| 关键词信息来源 1 | 错误日志中的 ERROR 级别关键报错信息（去掉时间戳、进程号等噪音） |
| 关键词信息来源 2 | 脚本文件名 |
| 关键词信息来源 3 | 报错涉及的类名、函数名、模块名 |
| “有用”的判断条件 | 经验中的 error_log 与当前报错特征一致或高度相似；或 Pattern 的触发场景与当前问题匹配；或 root_cause 与当前分析方向一致 |

## 三、检索调用示例

自动识别当前调测环境的产品：

```bash
python .opencode/skills/experience-engine/scripts/search_experience.py "SET AFRATTYPECFG 错误码 100017 MML命令 N5RATPARA" "421"
```

## 四、注意事项

| 序号 | 内容 |
|------|------|
| 1 | 检索时优先关注 Pattern 字段，因为它直接提供 `[触发场景] -> [修复动作]` 的复用规则 |
| 2 | 如果同一脚本有历史经验，优先级最高——说明同一脚本之前调试过 |
| 3 | Diff 字段可以作为修复参考，但需验证是否适用于当前版本 |
